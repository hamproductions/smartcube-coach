## 5. Methodology and decision record

### Re-ground from the visible product

The user’s complaint overrode earlier test-count completion claims. The public UI and source were inspected first. The visible object was the deployed page; its boundaries were the title/brand, default Today content, navigation, and actions. That inspection proved the product was mock-first, not merely cosmetically confusing.

### Replace rather than relabel fake data

The sample cockpit was not retained with a `Demo` badge. `sampleSolve.ts` and `sampleReconstruction.ts` were deleted, and Today now queries versioned IndexedDB repositories. This preserves the contract that coaching findings derive from persisted evidence.

### Separate software simulation from hardware evidence

Simulator controls remain because they exercise capture, event phasing, persistence, replay, and schema behavior. Every simulator label now states that it is software-only. Physical cube controls are enabled only when browser support exists, but hardware behavior remains unverified.

### Prefer a working training scramble over a deadlocking random-state worker

`randomScrambleForEvent('333')` deadlocked the production artifact because the generated worker path requested a missing unhashed asset. It was replaced with an in-process 25-move axis-safe generator. Preserve the wording `training scramble`; do not claim WCA random-state quality.

### Remove fake trainer surfaces

The cognitive panel had buttons and prose but no prompts, grading, persistence, or results. It was removed. The algorithm trainer remains because typed grading, timing, mastery, and persistence work. Its current content is intentionally classified as starter coverage.

### Honest static reco integration

GitHub Pages cannot run Bun. Only public solve `13444` is bundled with attribution. Arbitrary imports remain available only through the local Bun server. Do not broaden crawling or add unlicensed datasets.

### Evidence level separation

Unit/integration tests support deterministic code. `agent-browser` supports user-visible software claims. Neither layer proves physical Bluetooth behavior. The feature matrix uses `Working`, `Partial`, `Unverified`, and `Not implemented` accordingly.
